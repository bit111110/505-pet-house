# V6.0 第一階段：升級系統與屬性之石

穩定回復基底：V5.10.6，Git commit `5e1dff354f1e119701bfc91be59fd690ab5f3b81`。
開發分支：`feature/v6-upgrade`。本階段保留既有 API、對戰畫面與信箱掉落機率。

## 行為

- 升級分頁使用大型主畫面，包含「經驗糖果」與「屬性之石」。經驗糖果的單次、批量使用及防連點功能保留。
- 12 種石頭使用既有 `道具設定`／`學生道具` 系統。每顆固定增加 **5 點傷害**，只強化同屬性寵物的一個已解鎖技能。
- 一般、屬性與 30 級專屬技能均可強化；沒有遊戲設定的疊加上限。永久加成以十進位字串累積，避免大數加總失去精度。
- 技能清單顯示基礎、加成、最終傷害。既有對戰畫面不改版；共用技能計算會套用加成。
- 老師可用既有單次／批量發道具功能取得石頭。`grantAttributeStonesV600_()` 預留後端取得入口，本階段未接入信箱掉落。

## 新增 API

1. `getUpgradeBundleV600(studentId, token)`：回傳寵物、道具、戰鬥屬性設定、永久加成、石頭清單及升級資料結構是否就緒。
2. `useAttributeStoneV600(studentId, petId, skillId, itemId, requestId, token)`：驗證所有權、屬性與技能解鎖；扣一顆石頭並永久增加一個技能的傷害。

既有 `loginFastV596()` 新增 `authToken` 回傳欄位；原參數及原欄位保留。新 API 使用登入後取得的憑證，憑證保存在前端記憶體及後端快取，有效期最長六小時；過期／快取被提前回收時請重新登入。

## 新增資料結構

新工作表 `技能強化紀錄`：

| 欄位 | 用途 |
|---|---|
| 學號、請求ID | 操作歸屬與重複提交識別 |
| 寵物ID、技能ID、屬性、道具ID | 強化目標與使用的石頭 |
| 傷害加成、使用時間 | 永久加成與時間 |
| 狀態 | `PENDING`／`DONE`；只有 DONE 計入技能加成 |
| 道具原數量、道具新數量、道具列號 | 中斷後重試的扣除判斷 |

既有工作表沒有新增資料欄位。新增的道具 ID：
`STONE_LIGHT`、`STONE_EARTH`、`STONE_DARK`、`STONE_GRASS`、`STONE_WATER`、`STONE_POISON`、`STONE_FIRE`、`STONE_ELECTRIC`、`STONE_ICE`、`STONE_WIND`、`STONE_STEEL`、`STONE_CHAOS`。

## 部署與 setup

1. 在既有 Apps Script 專案貼入此版本 `Code.gs`。
2. 執行一次 `setupOrUpgradeV600()`：只補新紀錄表、缺少的 12 筆道具設定，並擴充道具類型下拉選單、清除設定快取。重複執行不重複新增，不發放道具、不清空學生資料、不改學生表 A 欄。
3. 若道具 ID 已存在但類型／效果值衝突，setup 會停止並提示，不覆蓋既有設定。
4. 更新既有 Web App 部署，沿用目前 `/exec` URL。
5. 發布 `index.html`、`app.js`、`style.css`，學生重新登入取得新憑證。
6. 用老師後台發少量測試石頭，確認同屬性強化、重新登入讀取與既有糖果使用。

## 重試與併發

- 石頭寫入與石頭發放使用相同 ScriptLock；只更新目標道具數量，保留其他學生資料。
- 前端先保存請求 ID，再送出；逾時後重試沿用原 ID，已完成的操作不再扣石。
- 後端先記錄 PENDING，再扣石，最後標記 DONE。重試可確認扣除前／後數量後完成原操作。
- 若道具列或數量被手動改動，後端會停止，不猜測或重複扣除。請老師核對紀錄與實際數量。
- 有 PENDING 操作時，該學生的新強化與石頭發放暫停，先重試原操作。
- 換裝置登入時，升級 API 會帶回尚未完成的請求 ID，讓新裝置重試同一筆操作。
- Google Sheet 不提供多工作表交易；請勿在有 PENDING 操作時手動調整石頭庫存或搬移相關資料列。

- 保留 `技能強化紀錄`、新增道具設定與所有學生道具數量；不執行任何清空、重設、刪表或自動退還石頭的函式。
